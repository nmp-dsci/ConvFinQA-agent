Highest val accuracy picks the checkpoint. 1.0 has it. 2.0 has the smaller p-value, because its fixes are spread over more conversations. Between checkpoints the differences are noise (§04), so either would have been a fair pick.

plateau

Nothing gained after one epoch

Accuracy rose over the first epoch and then held between 74.8% and 76.4%. A second pass over v2 did not help on val.

harness bug

3 lost turns, from one budget

The checked harness asks for 2 retries on the answer tool, but Pydantic AI caps the whole run at 1 (Agent(retries=…), default 1). A check retry followed by a malformed reply ends the attempt. It cost the same conversation (MRK 2013, 3 turns) at 0.5 and at 1.0. Every checked pass ran with the same cap, so the comparisons hold; it is left unfixed until the next round.

sampling

About 31–33 program questions flip every pass

At temperature 0.7 the student does not answer the same way twice. Two passes of the same weights, under settings that made no measurable difference, disagree on 31–33 program questions. Two neighbouring checkpoints disagree on 30–33. The weight changes are hidden inside that.

not separable

The 1.0 → 1.5 dip: net −9, p = 0.26

With about 33 questions flipping, a net of 9 is roughly 1.5 standard deviations. It could be a small real dip, but one pass per checkpoint cannot tell it from sampling. Its first mistakes on program turns went 30 → 37 → 31 across 1.0, 1.5 and 2.0. The same weights scored three times gave 34, 38 and 40.

size

Number turns move in steps of 0.8 points

One number question is 0.76 points of 131. The rise from 84.7% to 90.1% is 7 questions; the fall back to 87.0% is 4.

why

Openings are lookups

A prefix row is a conversation's turns before the teacher's first mistake, and conversations open with lookups. The aimed 600 are long conversations, and long conversations open with several lookups.

effect

Programs were not starved

Program examples went from 762 to 1,930 counted once per row, and every checkpoint gained on programs. The mix may explain why number turns gained relative to programs, not a loss on programs.

fix

Rebalance in the next round

If the next round targets programs, give program turns more weight, or down-weight lookup-only prefix rows, so the mix matches val's 64% program turns.

07 · Temperature, what it does and why 0.7

Fine-tuning moves the model's probabilities toward the teacher's choices. Temperature only decides how a token is picked from those probabilities afterwards: at 0 always the top one, at 0.7 usually the top one. It does not change whether training "sticks".

where low helps

Comparing checkpoints

Sampling is the noise in §04. A greedy pass removes most of it (vLLM is still not bit-for-bit repeatable), so checkpoints separate more clearly. It does not remove the other noise: only 100 val conversations.

measured

Lower was not more accurate

Epoch 2 at 0.2 scored 70.1% on val against 71.8% at 0.7 (20 fixed, 26 broken, p 0.74). That is why sampling stayed at 0.7 (D4).

why 0.7

Five reasons to keep it

Qwen recommends 0.7 · top-p 0.8 · top-k 20 for this model, and small models run greedily tend to loop on long outputs (ours are ≈ 8k-token tool conversations). Retries need a different reply: at 0 a re-attempt with the same context repeats itself. Greedy picks the best next token, not the best whole answer. Scores should describe the served setting. Data generation and voting need diversity.

08 · Why program turns still fail

Each wrong program turn is either the conversation's first mistake, or a knock-on: a later turn wrong because an earlier answer was wrong. First mistakes are classified with the project's own gold-derived walk (stage_scores.first_fault order: turn type, then operands, then plan, then the final answer).

sft2 1.0 · program turns

Half the wrong program answers are knock-ons

Val: 70 wrong = 30 first mistakes + 40 knock-ons. Test: 59 wrong = 35 first mistakes + 24 knock-ons.

test: first mistakes · knock-ons

With a clean history, program turns are right 83.7% of the time on val and 82.8% on test, against 90.7% and 98.0% for number turns. On test, 35 of the 37 first mistakes are program turns.

the gap

On test it is fetching values

Against Flash, the extra program first mistakes are almost all operand values: 18 against 7. Formulas, final answers and turn types are already at the teacher's level. 18 of the 35 are questions Flash answers right, so the teacher's data can in principle teach them.

val disagrees

Val's mix is different

On val the same model's program first mistakes are spread across formula (10), answered as a lookup (9) and values (7). With 30–35 cases per split, the kinds are noisy; across both, values (25) and formulas (20) lead.

aimed by val

The aimed weaknesses moved on val only

v2's 600 were picked by epoch 2's val error rates. On val: question 5 onward 55.9% → 70.6%, multiply 7/15 → 10/15. On test: question 5 onward 76.0% → 76.0%, multiply 6/13 → 2/13. Small samples, but aiming by val's weak buckets did not show up on test.
