02 · The harness, and why Pydantic AI comes before Deep Agents

The champion's harness is deliberately bare: no built-in tools, no inherited instructions, six calculators and a structured answer. So the best open harness is the one that adds nothing the model can see and still handles DeepSeek's thinking protocol correctly.

recommended · A

Pydantic AI MIT · already a dependency · upgrade 1.75 → 2.61

  • Reasoning round-trip works. Its DeepSeek provider stores reasoning as a thinking part and sends it back in the reasoning_content field (shipped in 1.26). That is the rule DeepSeek enforces with a 400.
  • The answer works like Claude's. An output tool named StructuredOutput carries SdkTurnResult, with one built-in retry. Our _correction loop sits outside it, unchanged.
  • The model sees nothing extra: the six tools plus the output tool, and the instructions as given.
  • Tracing is already on. mlflow.pydantic_ai.autolog() runs inside tracing.enable() and keeps the thinking parts in the spans.
  • The fine-tuning record is lossless. ModelMessagesTypeAdapter dumps each conversation with its reasoning and tool calls.
  • Version: upgrade to 2.61. The repo pins 1.75.0, from 1 April. 2.61.0, from 24 October, handles DeepSeek's thinking rules natively, as the table below shows.
  • One gap remains in every version. The DeepSeek profile matches deepseek-v4-*, so the new deepseek-flash id needs one explicit profile in llm.py (open issue #8353).
option · B

LangChain Deep Agents MIT · v0.7.32 · adds langchain, langgraph, langchain-deepseek

  • Its strength: it is the open-source analogue of Claude Code itself, with planning, a filesystem, subagents and summarisation. Since 0.7 it adds no base prompt of its own.
  • Blocked with thinking on:
    • No reasoning round-trip: issue #40219, with fix PR #40254 unmerged since 7 Sep.
    • ToolStrategy forces tool_choice, which returns 400.
    • ProviderStrategy sends json_schema, which DeepSeek does not accept.
  • Not lift-and-shift: the filesystem and subagent middleware cannot be removed, so the model always sees read_file and friends. A plain create_agent avoids that, but still has the DeepSeek problems.
  • Weaker record: reasoning is dropped from MLflow's LLM spans and from convert_to_openai_messages.
  • What it would take: a ChatDeepSeek subclass that re-attaches the reasoning, plus a custom output tool. The other route is thinking off, which changes the agent. Revisit when #40254 lands.

The smoke checks

C1Same contract

The recorded request has exactly SDK_PROMPT (sha equal) as instructions. The tools are exactly the six mcp__cfq__* plus StructuredOutput, with descriptions and schemas equal to the SDK's.

C2Answers parse

At least 95% of answered turns validate as SdkTurnResult within the allowed correction.

C3Tools do the arithmetic

Every program turn calls a calculator, and inline_arithmetic is false. The answer is a value a tool returned.

C4Reasoning survives

No 400 from missing reasoning_content. Reasoning tokens appear on most calls, and effort high is on the run.

C5Ceiling

No token budget exhausted rows. New tokens per conversation are reported.

C6Right model

Every response's served model id is recorded, and it is the same across the smoke and the full train.

C7Unanswered isn't wrong

A 429, 402 or 503 lands as unscored and aborts the conversation. The pass then finishes with --resume-from.

C8Same scorer

The CSV has every ROW_COLUMNS column, the stage panel computes, and the Story reads the run.

06 · Cost and time

The estimates are built from the champion's runs:

  • The champion's train draws: 630 answered turns.
  • Per call, assumed: 3–5 model calls per turn, about 12k tokens of context per call, and most input served from DeepSeek's cache.
