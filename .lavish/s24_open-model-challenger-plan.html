03 · The harness: the task stays fixed and the protocol is the model's own

The harness doesn't have to be Claude's. What has to match is the task, because the scorer reads the answers, the program and the stage record. How the model is driven can follow each lab's own conventions. Each item in the left column comes from backends/agent_sdk.py and config.py.

fixed: the task
instructions
sdk_v1's content: stages, number format and the ban on mental arithmetic (16,397 characters, about 4.1k tokens; see D4)
tools
The six calculator functions from pipeline/tools.py, {a, b} each. They are the only tools
answer
SdkTurnResult: turn_type, conv_type, sub_questions, program, retrieved[], answer, reasoning
conversation
One running history per conversation. Turn 0 carries the report. At most 8 model rounds per question, and one correction on a bad answer
ceiling
60k new tokens per conversation, counted the same way as the champion's (input increase plus output; cache reads excluded)
record
The pipeline's stage shape via result_to_capture, written to the same CSV columns
the model's own: the protocol
wire
The lab's own API in OpenAI chat format, with native function calls. No Anthropic-format shim
reasoning
The lab's own switch and effort parameter (for example DeepSeek's reasoning_effort), set to high
round-trip
The model's reasoning goes back to it across tool calls as the lab specifies. DeepSeek requires this, and other thinking models degrade without it
output
JSON in the final message (prompted), or a native schema where the lab supports one. Never tool-mode output, which broke thinking models here in 2026-09
sampling
Each lab's recommended settings for its thinking mode. DeepSeek ignores temperature in thinking mode, and V4-Pro ignores top-p as well
retries
The lab's own throttle and balance errors map to unscored, not wrong

Does DeepSeek have its own harness and a thinking-effort control? Yes, both.

  • DeepSeek Harness (dsh): deepseek-ai/deepseek-harness, built by DeepSeek AI, MIT, TypeScript on Node. Published 2026-08-13, last pushed 2026-10-17, npm @deepseek-ai/dsh@0.2.1-rc.2. It is a developer preview: the README warns of "compatibility-breaking changes", so the version would be pinned.
  • It can drive one conversation as one session. dsh --profile headless --json "…" answers one task and streams newline-delimited run events, and --session-id <id> resumes the same session for the next question, just as the champion's session carries a conversation. There are also acp and sdk (stdio JSON-RPC) profiles.
  • It can host the six calculator tools. The @deepseek-ai/dsh-mcp-client plugin loads an external MCP server over stdio and registers its tools as native tools. A small Python MCP server around pipeline/tools.py serves them. A profile --patch overlay sets the sdk_v1 instructions and switches off the coding tools.
  • Effort. The harness's DeepSeek adapter offers off, low, high and max, defaulting to high. off sends thinking: disabled, and an unsupported level is refused rather than silently swapped. On the API, reasoning_effort takes low, high or max. A request for xhigh is treated as high, so for V4-Pro "high reasoning" means high and the step above it is max.
  • What it costs here: a fourth runtime (dsh) that drives the CLI per question and reads its run events into the stage record. The answer comes back as text and is parsed the way the champion's fallback path already parses text. Its programmatic-tool-calling mode has to stay off, because the model must not compute in code instead of calling the calculator (check C2). About half a day on top of P0.
recommended · A

One open harness, a profile per lab

  • A plain tool-calling loop over each lab's own API: the shape τ-bench measured the leaderboard in. The candidates are compared as they were ranked.
  • Built on pydantic-ai 1.75, which the repo already runs. mlflow.pydantic_ai.autolog() already traces it, so the evalloop gets spans for free, and token usage is exact per call.
  • s23's backends/student.py becomes this runtime's Modal vLLM profile.
  • Cost: a third runtime has to be accepted by the judges (story.py:1210–1222, 1591+, prior_runtime, _arm, the gates-ledger runtime). Each lab's reasoning round-trip has to be right. A gap in A mixes model and harness effects, which is what P4 is for.
own harness · B

The lab's own harness

  • The mirror image of the champion, which is Claude in Claude's own CLI. DeepSeek V4-Pro in DeepSeek Harness (headless, MCP calculator, effort high) is ready to build. Kimi K3 in Kimi CLI (Apache-2.0, print mode, stream-json, MCP config) is the other option.
  • Cost: one adapter per harness, and each harness's coding tools have to be switched off. dsh is a developer preview. GLM and Qwen3.8-Max have no harness of their own that I found.
optional control · C

Claude's harness, open model

  • The finalist runs in the Claude Agent SDK through its lab's Anthropic-format endpoint (DeepSeek, Z.ai, Moonshot and Model Studio all have one), with everything else as in the champion. Only the model differs, so this isolates the model effect.
  • Cost: a provider billing route, provider pricing and the reroute safety fix (§04). Anthropic does not support non-Claude models through the CLI.
not doing

Ruled out

  • A local LiteLLM proxy: the platform's rule zero forbids a project-local gateway. The shared M4 gateway is not built yet.
  • OpenRouter as the main route: one model can be served by several hosts at different quantisations. Use it only as a fallback, with the provider pinned.

05 · The run, with a gate before every spend

P1 · Smoke: seven contract checks per candidate

3 train conversations (about 12 questions) per model, run with run --runtime open_agent --open-profile … --open-effort high. DeepSeek goes first because its key is already in ~/.env. A model that fails C1 to C3 after one profile fix is dropped. The smoke run's measured tokens × 33 gives each model's test-pass price before anything bigger is spent.

C1Answer

At least 11 of 12 turns parse into SdkTurnResult within the one allowed correction.

C2Tools

Every program turn calls a calculator tool, and the answer is a value a tool returned. No inline arithmetic.

C3Reasoning is real and kept

Reasoning tokens are present on most turns at the requested effort, and no request fails for missing reasoning (DeepSeek's 400).

C4Ceiling

No conversation reaches token budget exhausted. New-token use is within 2× of the champion's on the same 3 conversations.

C5Cost

Cost is priced from per-call usage. A projected test pass above $40 stops for your approval.

C6Right model

Every response's model id is the candidate. Nothing is served by a fallback or a smaller model.

C7Unanswered isn't wrong

Any throttle or balance error in the smoke run lands as unscored. The mapping is unit-tested in P0 against each lab's documented error texts.

P2 · Train screen on seed 2027Run run --split train --version sdk_v1 --runtime open_agent --open-profile P --open-effort high --train-seed 2027 --stop-at-first-wrong for each candidate that passed P1. The 100 conversations are id-for-id the champion's own early-stopped draw, so they pair per conversation. A candidate is a finalist if it passes the per-conversation check the verdict's train veto uses. At most two go on, best first. Under D2, DeepSeek V4-Pro is screened twice, once in the open harness and once in DeepSeek Harness. Only its better arm can go on. Review stop: you see the screen before any test pass.≈ $12–25 per candidate · train only, test untouched
P3 · Finalists: seed 2028, then one test pass eachThe second train seed completes the veto evidence. Then one --split test pass on eval_loop_v2, paired against sdk-evalloop-test100-sdk_v1·s1-20260905_174627 and its train draws by model_swap_verdict. Test is opened once per finalist. Never sending every candidate to test and keeping the best is what keeps the verdict honest.≈ $20–50 per finalist · subject to the D6 cap
P4 · Optional: a harness control for the finalistRun the same model in C (Claude's harness, through the lab's Anthropic-format endpoint), or in B for Kimi (Kimi CLI), for one test pass. DeepSeek's own harness is already covered by the P2 screen under D2. A finalist that falls short narrowly in A but passes in C points at the harness. If it falls short in both, the model is the limit.≈ $10–28 · one test pass · D2
