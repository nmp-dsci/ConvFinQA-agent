s36 · ConvFinQA-agent · 2026-11-12 · plan · the trace builder, proven before it is used · feeds DPO v2 · branch dpo

Build a trace writer that knows the answer, and prove it is indistinguishable from a real right answer before it writes a single chosen.

438 questions in dpo_v1 have no right try in 8 (s35 §03b). They block 499 more, and they are exactly where the student most needs a chosen. The trace builder takes the question, the history, the page and the gold answer, and writes the turn the student should have written: sub-questions, retrieved values, calculator calls and a StructuredOutput answer. Before it touches the 438, it is run on questions where we already hold a known-right trace, with that trace hidden. It has to (1) pass deterministic validity gates, (2) recreate the real trace's decisions, and (3) fool an LLM judge that is shown both and asked which one the builder wrote. A control run proves the judge can tell when it should. Only a builder that clears all three on a sealed validation set is deployed.

validity gates (deterministic) · recreation fidelity (against the hidden real trace) · judge discrimination (2AFC, with controls)

02

B · The builder: arms to try on dev

The builder's output must be a turn the student could have written, so the default writer is the student itself, given the answer (STaR's rationalisation). A stronger model is the fallback. Which arm deploys is decided by §04, not chosen up front.

ArmWriterWhat it is toldWhyRisk
B1 leadsft2-e1 (student), 8 samples, its own harness and toolsThe normal turn prompt plus a hint: "The correct final answer is X. Work it out from the report; do not mention this hint."Closest to on-policy: its own style, tokens and tool habits, so DPO's chosen is a turn it already finds likelyOn its 0/8 questions it may not find a path even with the answer, or may force one (choosing operands to hit X)
B2sft2-e1 with hint = answer and gold programAs B1, plus gold's program (subtract(206588, 181001), divide(#0, 181001))Pins the operations; the student still has to locate the operands and write the workingProgram strings can leak into the reasoning; the student may copy gold's literal numbers without retrieving them
B3 fallbackllm_react_v1 (DeepSeek Flash, the SFT teacher), same toolsAs B1The student was SFT'd on this writer, so it is the nearest off-policy style. CheapOff-policy. The judge should detect it more easily (it is the positive control, §04)

Every arm runs through pydantic_ai_checked with the calculator tools, so a built trace's numbers come from real tool calls, not from text. The stored training row is the turn without the hint: the plain prompt, then the built turn as the chosen. Abstaining is allowed: a builder that cannot reach gold from the page returns nothing, and that is counted, not forced.

04

V · Proving it: recreate known-right traces, and fool a judge that has been shown it can tell

Reference set. Questions in dpo_v1 train where the student already has a clean right try. Hide every try, give the builder the gold answer, and compare what it writes against a held-back real right try. Stratified to look like deployment: deployment is all-hard (0/8), so the validation leans hard.

Three measurements

V1

Gate yield

Share of questions with ≥ 1 candidate passing G1–G6, and of candidates. Abstentions and each gate's failures reported separately, by stratum.

V2

Recreation fidelity

Against the hidden real right try: same turn type; same program up to execution equivalence; same operand values; same retrieved sources (cell/row); sub-question count; reasoning length within the real distribution. Reported as agreement rates with Wilson CIs. A second real right try of the same question is the ceiling: two real traces disagree too, and the builder is judged against that, not against 100%.

V3

Judge discrimination (2AFC)

The judge sees question, history, page, and two traces in random order: one real right try, one built. "One of these was written by a model that was told the answer. Which one?" Plus a reason. Accuracy with a Wilson CI over questions; ties are not allowed.

The judge has to be shown it can tell, or its "can't tell" proves nothing

RunPair shownExpected judge accuracyWhat it proves
C0 nullreal right try vs another real right try of the same question (one labelled "built" at random)≈ 50%The judge's chance level on this data, with its CI. Any position or length bias shows here
C1 positivereal right try vs B3 (Flash with the hint)clearly above 50% (target ≥ 75%)The judge has power: a different writer is detectable
C2 positivereal right try vs a B1 trace with the hint left in the reasoning (an injected leak)≥ 90%It catches the failure G5 exists for, so a leak G5 misses would not pass V3 either
T testreal right try vs the candidate arm (B1 or B2)indistinguishable from C0The builder's traces read like the student's real right ones

Judge: Claude through evalloop/sdk.run_structured on the subscription (the teacher's and confidence judge's chokepoint, so it is traced). It never sees gold or the hint, only the two traces. Positions are randomised per question and each question is judged twice with the order swapped; a judge that flips with the order is scored as a tie (0.5). A second, absolute check scores each trace alone for faithfulness (does the working support the answer?) on the confidence judge's six checks; built traces must not score below real ones.

Dev is for iterating on the builder's prompt and picking B1 vs B2; the sealed set is read once for the arm that dev picked. A fail on the sealed set goes back to dev with a new arm, and a new sealed draw (from the 2,717 + 725 left), never a re-read of the old one.

06

D · Deployment: the 438, then DPO v2

  1. Build. The passed arm on all 438 (416 train, 22 eval), N = 8 candidates each, every candidate through G1–G6. The 97 "right value, wrong form" questions also get a format chosen (the student's own try, answer restated), kept as a labelled subset so its effect can be read alone.
  2. Spot check. 30 gated traces read by hand against the page, stratified by s35's categories (sign, same-wrong, scattered, near). A flagged gold (gold_suspect) is dropped, not built to.
  3. Pairs. The built chosen vs the student's 8 clean wrong tries, cap 4, the same selector. Tagged source=built beside s35's source=sampled, so DPO v2 can be read with and without them.
  4. Walk on. The built turn becomes the history, and the student samples the 499 questions behind it at 8 tries: more on-policy pairs.
  5. DPO v2. s35's 2,448 sampled pairs plus the built ones. Its pilot is compared against DPO v1's on val. Test 100 stays closed.
