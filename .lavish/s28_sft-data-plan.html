Two points in the brief to settle first.

  • tau-telecom-sft has no 6B model. Its student is Qwen/Qwen3-4B-Instruct-2507 (4.0B, non-thinking, pinned at cdbee75), and its Mac smoke run used Qwen3-0.6B. I planned on the 4B, because it is the model, recipe and Modal weights volume you've already used (D1).
  • "Keep as is, no other runs" was about the challenger. Building enough training data needs one DeepSeek collection run on the train split. It is a data run, not a new challenger, and it waits for D4.

Test 100 is the holdout (your note). The 100 conversations of eval_loop_v2 test are used for one thing: scoring the base student and the fine-tuned student, paired question by question. Flash never collects on them, no row is built from them, nothing is selected or balanced by looking at them, and every one of their report pages is kept out of training (150 pages, with the sealed holdout). The separate sft_v1 val set (100 conversations on other pages) only picks the epoch. For more data, the training draw grows (your note). The same seed's larger draw contains the smaller one, so nothing already collected is wasted, and failures aren't resampled.

01 · Your approach, reviewed

In short: the teacher, the harness and the recipe are the right choices, and better than s23's Sonnet route. There are three adjustments.

right

An open-weights teacher

DeepSeek's platform terms allow training other models on its outputs (checked in s23), and V4.1 Flash has open weights. That satisfies tau's Rule 2 ("agent turns come from open-weights models only"), which s23 had to set aside to use Sonnet. Its reasoning is recorded too; Sonnet's never was.

right

The same harness at train and test

The student would run in llm_react_v1's own Pydantic AI loop, with the same prompt, the six mcp__cfq__* tools and the StructuredOutput answer. So the rows are in exactly the format the student meets at test time, and the existing gate scores it.

right

tau's recipe on Modal

TRL + PEFT LoRA on one L4, vLLM serving with the hermes tool parser, a mask check on every row, data-hash checks, and the run-folder contract. It took tau's 4B from 6/40 to 17/40 on 518 rows. All of it can be copied.

adjust

The ceiling is Flash, not Sonnet

Flash scored 87.7% on test, 2.87pp under the champion. A student trained on Flash's clean conversations aims at Flash. Gold-checked and resampled rows can lift it slightly, but the honest target is "how much of the gap from base to Flash does it close".

adjust

Keep the reasoning, don't drop it

tau dropped its teachers' reasoning. Here that would discard the most useful signal: DeepSeek reasons before each calculator call, so the trace is the plan that drove the action. §03 shows how to keep it without breaking the chat template.

adjust

Pick the student, then the row shape

The row shape follows from whether the student thinks in hidden <think> blocks. Qwen's templates drop earlier turns' hidden reasoning when serving, so the shape is not a free choice (§04).

02 · What llm_react_v1 records, and how ready it is

The source is the per-run trajectories.jsonl.gz artifact: one line per conversation holding Pydantic AI's full message history. As in tau, the MLflow traces are for browsing only, because prompts are stored there by reference and payloads are trimmed. N1 · the detour collapses. The struck lines go. If the refused response carried the reasoning, it moves onto the call. The student learns to answer straight through StructuredOutput and never sees a refusal it would only learn to copy.

Reasoning becomes visible text. DeepSeek's thinking goes in a <reasoning> block in the same assistant message, before its tool call. A non-thinking template keeps it, so the student writes it at test time and later turns see it, exactly as in training.

Loss on the assistant's tokens only (assistant_only_loss, tau's mask check on every row): the reasoning, the calls and the final JSON. The prompt, document, questions and tool results are context.

04 · Conversation or conversation × question?

Either way, selection is by conversation, as you set in s23: a conversation is kept whole or dropped whole, every question of a kept one is used, and the split is by report page (sft_v1). The question is only how a kept conversation becomes training rows, and that depends on whether the student thinks.

recommended with tau's 4B

A · whole conversation

  • When it's right: a non-thinking student (Qwen3-4B-Instruct-2507) with the reasoning written as visible <reasoning> text, which the chat template never strips.
  • Scored on test 100, the holdout, base and tuned alike.
  • Train equals serve: at test time the student's earlier answers, reasoning included, are in its context, exactly as in the row.
  • Size: median 7,979 tokens, p90 9,364, max 18,299 (DeepSeek's count; Qwen's goes in the data card). It fits tau's max_length 24,576 with no truncation.
  • Matches tau's row shape and the rule you set in s23 rev 6.
  • Cost: ≈ 530 rows × 8k ≈ 4.2M tokens per epoch, ≈ 5 h and ≈ $5.50 for three epochs on an L4 at tau's measured 715 tokens/s.
only for a thinking student

B · conversation × question

  • When it's right: a thinking student (Qwen3-4B-Thinking-2507) that puts DeepSeek's reasoning in hidden <think> blocks.
  • Why it's needed then: Qwen's template keeps <think> only after the latest question, so at test time earlier turns arrive without their reasoning. A whole-conversation row would train with reasoning the model never sees when served. tau's plan §6 reaches the same conclusion.
  • Cost: ≈ 2.8× the tokens, ≈ 14 h and ≈ $15 on an L4 (or a faster GPU). It also needs vLLM's --reasoning-parser, which tau never ran.
  • Gain: reasoning stays out of the visible answer. That doesn't matter here, because the harness reads only the tool calls.

05 · Building the data

The gates

They work like tau's F1–F10: a conversation is dropped whole and charged to the first rule it fails, and every drop goes to drops.jsonl with its rule. The gold-stage gates are s23's G1–G5 and T1–T5, with the two redefinitions it measured. The rest are specific to DeepSeek.

RuleKeeps a conversation only if…Source and why
F1every question's answer is rightThe CSV's correct. Flash was right to the end on 63 and 62 of the two train100 draws.
F2it is in the training draw, on no test, holdout or val pageThe committed manifest (sft_v1, or sft_v2 if the draw grows), never a run's own draw. This keeps out all 100 test conversations and their page siblings, the sealed holdout, and the 7 seed-2028 conversations on val pages.
F3it is complete, with no turn error, rate limit or NO_VALID_ANSWER replyThe CSV's error and unscored and the trajectory. Collection runs every question, not stopping at the first wrong one, so a kept conversation has all its questions.
F4each turn's type, plan, operands and calculator check against golds23's G2–G5. Operands read a value carried from an earlier turn as present, and the plan is compared with gold's own program value, not the rounded answer.
F5tool use is clean: no failed or repeated call, calls follow the plan, arguments come from the document, an earlier return or a DSL constant, and the answer is the last returns23's T1–T5, read from the trajectory's calls and returns.
F6every turn was answered on its first attemptNo correction re-ask in any user message (0 so far). Record the attempt count in the capture too.
F7no reasoning block is runaway (≤ 2,048 tokens)The 8 blocks over 8,000 characters all sit in failed conversations; this keeps the rule explicit.
F8the rendered row fits max_length 24,576The longest so far is 18,299 DeepSeek tokens. Over-long rows are dropped, never truncated (tau's rule).
N1Normalise, don't drop: collapse each text-answer detourKeep the StructuredOutput call; drop the refused text, the retry prompt and the reasoning about the retry. The counts go in the card (48 of the 116 clean conversations so far). A test checks the call's arguments equal the refused text's JSON.

Expected yield, an estimate from the train100 draws: about 63% right to the end, and about 94% of those past the stage gates (s23's probe on Sonnet), so ≈ 59%. For scale, tau trained on 518 rows. More data comes from more conversations, never from re-running failures: Flash's full train passes reproduced the smoke conversation for conversation, so a re-run mostly repeats itself.

09 · Risks

A lower yield than 59%. The draw then grows again (n 1,500 gives 1,314 conversations, ≈ $3.01 in total). Resampling isn't the fallback: DeepSeek in thinking mode looked close to deterministic here, and the smoke reproduced conversation for conversation.

Thin hard cuts. Flash's failures are concentrated in long and Type II conversations, so the clean set under-represents them. The data page shows coverage by cut before any training.

Format failures at test time. A student might still write text answers. Rows teach the tool call, and scoring counts format failures separately, as s23 planned.

A long, repeated context. The 17 KB prompt plus the document is ≈ 5.6k tokens on every row. A shorter student prompt would cut cost but confound base vs tuned, so it's D5.

Modal can't reach MLflow (tau's lesson). Training runs are synced back afterwards, and Modal jobs refuse uncommitted src/.

tau's L4 throughput (715 tokens/s against an estimate of 1,100–1,500) is the basis of the time estimate. A measured two-step run comes before the full job, as in tau.
