02 Why it happened, and what changed

The first two causes share a shape worth naming: the read-only routes are written to degrade rather than 500, which is correct — and which is exactly why an artifact missing from the image failed nothing. No build broke, no route errored, no smoke test complained. A page simply rendered its “not yet run” state on the deployment whose only job is to show it.

C1 · The image never carried story.json, readiness.json or any traces Dockerfile

COPY evaluation/mlflow_snapshot.json evaluation/registry.json was the whole list. story.json alone feeds the entire Runtimes page, the campaign track, the progression chart, the judge panel and four landing tiles. .traces/traces.db is 57 MB of gitignored dev state, so a cold container browsed nothing.

Fix
story.json, readiness.json, evaluation/judge/ and a new traces_snapshot.jsonl.gz are copied in.
Traces
New tracking/trace_snapshot.py exports the store to gzipped JSONL — 6 MB for 8,408 turns — and seeds a store that has no turns of its own. Emptiness is the guard, not the deployment mode, so a dev machine keeps what it measured and a fresh checkout gets the record.
Verbatim
Rows are copied with their trace_id and created_at intact. Re-recording them would stamp 8,000 historical turns with the image’s build time and report a batch evaluation as a live traffic spike inside /metrics/production’s 24-hour window.
Command
uv run convfinqa-mlflow traces-snapshot

C2 · The readiness scorecard, same cause Dockerfile

evaluation/readiness.json is committed and CI-checked, and was never copied in. Three surfaces render it from one component, so all three went dark at once: the landing strip, Architecture §13, and the Readiness page itself.

Fix
Copied, and covered by the artifact contract below.

C3 · /admin/experiments is both an API route and a page serving/app.py

/admin is an API prefix and a UI route prefix, and this one path is spelled the same on both sides. FastAPI matches the API route first, so the SPA fallback never ran: a bookmark, a refresh or a shared link returned raw JSON. Dev cannot catch this — Vite’s proxy already hands document requests back to the client router, so the collision is invisible until it is public.

Fix
The same rule Vite applies, applied on this side: a GET/HEAD under /admin whose sec-fetch-dest is document gets the SPA shell. fetch() sends */* and the SSE client sends text/event-stream, so no real API call is caught.

C4 · The board named the pipeline bundle, not the agent that answers the champion question

Serving was already sdk_v1 — SERVING_RUNTIME=agent_sdk is the default and sdk_champion is sdk_v1 in the registry. What was wrong is what the app said about it: the landing lamp read champion v8, the four-agent pipeline bundle, which answers none of a visitor’s questions.

The registry keeps the two aliases apart on purpose, and that stays: registry.promote refuses to point champion at an sdk version, because serving builds four agents from it and an sdk version there is a champion nothing can construct. So “the champion” is only well defined once you know the runtime.

Fix
/healthz now resolves it once and reports serving_champion: "sdk_v1". The top bar and the landing lamp read that field instead of each re-deriving the rule — one of them had drifted.
Result
The champion lamp reads sdk_v1 and links to Runtimes, where the evidence for it is.

03 What now ships, and what stays dev-only

The rule: every committed artifact a read-only route opens goes in the image. Dev state — the LM cache, the MLflow file store, the raw trace DB — stays out and ships as an export.

Two differences that are deliberate and stay

8 filings, not 260. Chat can only answer what the recorded pack holds, and the eyebrow says so honestly. Cost / latency tiles read “—”. The landing reads the demo source group, which carries no timing of its own — a turn recorded at 6.7s and replayed in 2s is not a 2s turn, and the app refuses to blend the groups. The real numbers are now on the Traces page under serving and eval, where they belong.

04 How this stops coming back

Both failures were silent by construction, so the guard has to assert the payload, not the status code.

  • tests/test_demo_image.py — one table, SHIPPED_ARTIFACTS, mapping every committed artifact to the route that opens it. It parses the Dockerfile’s COPY lines (including \ continuations) and fails when a listed artifact is not carried, and separately checks .dockerignore does not exclude one. It also drives the app with a mounted SPA bundle and asserts /admin/experiments answers HTML to a navigation and JSON to a fetch().
  • scripts/demo_smoke.sh — runs against the live URL on every deploy. Four new assertions: /eval/campaigns carries an sdk_champion, a champion_track and a runtime_comparison; /eval/readiness returns nine rows; /traces/stats reports more than a thousand turns; and /admin/experiments returns a page to a browser. An empty state is a legitimate answer in dev and a deployment bug in the container — the smoke test is where that distinction is enforced.
  • tests/test_trace_snapshot.py — the export round-trips verbatim, loading twice adds nothing, a store with its own history is never seeded, a snapshot from a future build loads with unknown columns dropped, and an unchanged store exports byte-identical bytes so it never shows up as a spurious git diff.

06 One thing I did not change

It is a real gap and it belongs to your earlier feedback rather than to this task, so it is flagged rather than done.

The production-metrics window is still 24 hours

You asked earlier for traces “over all time, not the last 24 hours, and over all models”. The traces table is already all-time and now carries all 8,408 turns in prod. The metric cards above it are not: they aggregate a 24-hour window, so in prod every seeded turn falls outside it and the cost and latency cards read “—”. Widening that window is the same one-line question in dev and prod, and it would make those cards mean something on the demo. Say the word and it goes in this branch.
