Haiku 5.5 runs the champion's prompt for a sixteenth of the price, and falls 3.2 points short of it

The challenger sdk_v1 · claude-haiku-5-5 · effort high was scored on exactly the questions the champion sdk_v1 · claude-sonnet-5 · effort high was scored on, and paired against the champion's committed runs. Sonnet was not re-run. On test100 it got 87.4% against 90.5%. The whole loss is on program turns, it is significantly worse, and its 95% interval reaches −6.8pp, more than twice the 3pp margin agreed before any Haiku 5.5 number existed. registry.promote_agent refused it, and the registry is byte-identical. The pass cost $0.73 against $11.83, and measuring that honestly meant fixing how every SDK pass had been priced.

05 · cost and speed

Every SDK cost on record was overstated, and the CLI did not know the new model's price

Measuring cost properly turned up two errors, both now fixed in code (tracking/cost.py, tracking/sdk_cost.py, convfinqa-evalloop backfill-sdk-cost, pinned by tests/test_sdk_cost.py).

1 · Running totals were summed. The CLI's total_cost_usd is the session's running total (one Single_RE conversation: $0.015 → $0.040 → $0.066 → $0.093), but sdk_cost_usd summed it over every turn. That overstated every SDK pass 2.2–2.6×. sdk_v1's test pass was recorded at $27.62, and the price paid was $11.83 (the last total of each of its 100 conversations, read from the archived traces).

2 · Haiku 5.5 was priced at 50×. The bundled CLI 2.1.259 predates the model. It prints unrecognized_model, still sends the model, effort and thinking as asked, and prices the model on a fallback card of $5 / $25 per MTok, with 1-hour cache writes at 2× and reads at 0.1×. That reproduces a recorded turn to the micro-dollar ($0.2168665). Haiku 5.5's rate card is exactly 1/50 of that on every component while each prompt is ≤100K tokens. The largest call here was 46K.

The one ceiling error is a first-batch effect that both arms paid. A session's first API call carries 7 tools and every later call carries 65. The conversations that open a pass together each write that ~50k prefix to the cache in a single turn, against their own 60k ceiling, before any of them can read it. In Sonnet's baseline, three of the first four conversations (INTC, IPG, STZ) wrote 55–57k in one turn and peaked at 59–61k. Its IPG crossed 60k only after its last turn. Haiku's IPG crossed one turn earlier (its newer tokenizer counts more), so q2 was not attempted. Sonnet got that question wrong too, so the pair is unaffected.

07 · caveats and what next

What this does and does not show

Caveats

  • One pass per arm. There is no run-to-run variance estimate. The CI is over conversations, not over reruns.
  • The two arms ran six weeks apart (2026-09-05 vs 2026-10-15). Sonnet was deliberately not re-run, per the owner's rule.
  • The prompt was written for Sonnet. sdk_v1 was distilled and validated on Sonnet. This measures the model swap alone, not the best Haiku 5.5 agent.
  • The scorer's 3 dp comparison touches a handful of flips on each side. §01 shows the verdict survives either reading.
  • Serving changed in this build. It now runs the champion record, Sonnet 5 at high. It had been on an unscored low since 09-10.

Options, none taken

  • A Haiku-tuned prompt. The two dominant failures, giving up on values that are present and backwards subtractions, are rules a prompt can state. A teacher pass over Haiku 5.5's train failures would produce a candidate. It would change prompt and model at once, so it needs a gate against the champion on test, not the model-swap rule.
  • Haiku 5.5 at xhigh / max. Effort is part of the agent and is cheap to try at ≈ $1 a pass. Same rule, same pairing.
  • Keep Sonnet 5. This is the default, because the rule says so.
